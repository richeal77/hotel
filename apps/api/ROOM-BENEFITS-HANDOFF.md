# 房型报价与权益后端交接

三端共享版本为 `0.4.0-draft`。总控在 `docs/contracts/room-benefits-handoff.md` 记录了 M1 冻结文件的哈希。

## M1 验收与 M2 待测项

| 测试 | 验收断言 |
| --- | --- |
| 报价关房 | 两晚任一晚关房即拒绝。已取得报价后关房，提交失败且房量、权益和报价消费状态均无变化。 |
| 最后一间 | 独立报价同时提交时仅有一笔订单成功，两晚库存各占一间。取消后两晚各归还一间。使用相同或不同幂等键重复取消均不再释放。 |
| 并发领券 | 对同一资格使用不同幂等键并发提交，至多一笔成功。使用原幂等键重放返回原响应，库存与流水只变化一次。 |
| 重复发礼 | 新订单从 `booked` 转 `checked_in` 时核销锁定权益，再发入住礼和固定额返住金。重复请求、旧订单状态操作、取消和未入住均不产生此类新权益。 |
| 过期 | 测试新人资格到期前与到期时刻，校验下单所选权益在入住日的有效性，并验证已锁定权益按订单快照办理入住。 |
| 未入住跑批 | 门店时间次日 12:59 保留待入住订单，13:00 到期订单释放各晚房量及权益。重复运行不二次释放，并发办理入住仅允许一种终态。 |
| 首次初始化 | 分别在空 JSON 目录和隔离 MySQL 库验证可启动、重复初始化安全、既有数据保留，且集成库没有导入演示账本。新账本的默认配置以冻结版为准。 |

M1 覆盖报价关房、最后一间、报价到期、基本入住状态转换、未入住、JSON 首次初始化及重启、订单列表和开关。新人券并发领取、权益过期、重复发礼、入住返住金及全量后台审计待 M2 实现。M1 报价拒绝非空的权益选择，办理入住只接受空活动选择。

## 联调启动

从 `hotel/` 运行 `pnpm run test:api`。以下启动命令从 `hotel/apps/api/` 执行。

```sh
APP_ENV=local-demo CONFIGURED_BOOKING_ENABLED=true go run ./cmd/server
```

现有集成服务需要先从本地环境提供 `MYSQL_DSN`、`WECHAT_APP_ID` 和 `WECHAT_APP_SECRET`。使用专用集成库执行现有迁移后启动服务。

```sh
go run ./cmd/migrate
APP_ENV=integration CONFIGURED_BOOKING_ENABLED=true go run ./cmd/server
```

默认地址为 `http://localhost:8080/api/v1`。联调员工账号可用既有命令 `go run ./cmd/staff -username m1_admin -name "M1 admin" -role boss` 建立，密码从 `STAFF_BOOTSTRAP_PASSWORD` 环境变量读取。住客走集成环境 WeChat 登录和已验证手机号。

`CONFIGURED_BOOKING_ENABLED` 默认为关闭。关闭后仍可取消已提交的新单、查看新单详情和执行未入住处理。配置化注册与活动开关在 M1 能力接口中固定为关闭。未入住任务在启动时执行并每分钟检查，补处理到期的已预订订单。

本地 JSON 使用演示账号，通用订单列表依冻结契约保留旧订单。可用管理端新订单详情接口检查 JSON 中的 M1 订单。配置化通用列表使用 MySQL 集成模式验收。

## 迁移及验证

1. 在独立集成库备份后运行 `go run ./cmd/migrate`。迁移 002 把 M1 配置和订单存到 `configured_booking_store`，报价另存到 `configured_booking_quotes`，写入共用既有 `store_revision` 行锁。初始业务数据为空，重复迁移保留数据。系统在报价过期七天后清理报价，订单保持原报价快照。此布局与技术方案建议的拆表不同，接受前需由总控评估。迁移命令拒绝 `-from-json`，避免导入演示订单和账本。
2. JSON 首次加载会将完整的旧分文件数据写为 `store.json`，旧文件保留。此后以 `store.json` 为准，每次成功更新原子替换整个快照。JSON 模式只运行一个 API 进程。
3. 在仓库根执行 `GOFLAGS=-count=1 pnpm run test:api`。首次 MySQL 初始化测试额外需要 `API_TEST_MYSQL_DSN` 指向专用空数据库，测试会写入测试房型。该测试在无 DSN 时跳过。

## 联调注意

- M1 使用 10 分钟报价有效期和最多一年的日期范围。当前 OpenAPI 未把这两项写成约束。
- MySQL 实例验证和三端联调仍待隔离环境执行。M2 需要把权益核销及发放接入新订单入住事务，旧演示订单流程独立保留。

## 已提交总控的下一版澄清

- 库存 GET 引用的 `from`、`to` 在 OpenAPI 中可省略，技术方案按区间读取。M1 实现要求同时提供两项。
- 资源不存在时统一返回 HTTP 404 和 `NOT_FOUND`，冻结版没有在每个对应路径逐项声明。
- 将报价有效期、日期范围上限和 MySQL 持久化布局纳入下一版评审。
