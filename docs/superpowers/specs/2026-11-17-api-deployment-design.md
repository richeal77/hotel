# 后端双环境部署脚本设计

## 目标与范围

在 Mac 的 `hotel` 仓库运行一个脚本，将 Go 后端部署到同一台 ECS 的测试或线上环境。脚本不安装或修改宝塔、Nginx，不上传微信小程序和工作台。用户可用 `--address` 传入当前环境的外部访问地址；域名未就绪时用 IP 加端口，域名就绪后用域名。

## 已选方案

比较过共用 8081、轮流停服和两套端口常驻。选两套端口常驻：线上服务使用 8081，测试服务使用 8082。这样测试部署不停止线上服务。当前仓库生产分支为 `main`，不是 `master`。

| 模式 | 源码 | 运行环境 | 监听 | 数据 |
| --- | --- | --- | --- | --- |
| `test` | Mac 当前工作区，包括未提交改动 | 默认 `APP_ENV=local-demo`，后续可单独配置为 `integration` | `0.0.0.0:8082`，供 IP 测试 | 独立测试目录或独立测试库 |
| `production` | 执行时获取的 GitHub `origin/main` 提交 | 强制 `APP_ENV=production` | `127.0.0.1:8081`，由用户配置的 Nginx 对外提供 HTTPS | 独立线上 MySQL 库 |

当前 `origin/main` 只有演示版后端，无法以 `APP_ENV=production` 启动。线上模式在生产代码和数据库配置就绪前必须明确失败，不能回退到演示模式。

## 脚本行为

命令示例：`./scripts/deploy-api.sh --mode test --address 39.105.122.224:8082`；域名就绪后使用 `--address api.example.com`（生产）或独立测试域名（测试）。IP 地址用于 HTTP 测试；域名地址用于 HTTPS 检查。`--address` 不改 Go 程序监听端口，也不改小程序源码，只用于校验、部署后的连通检查和打印 API 地址。

每次执行依次：检查参数、Git/Go/SSH 和目标端口；为所选模式准备源码；运行后端测试和 Linux amd64 编译；通过 SSH 22 上传新版本；切换该环境的 `current` 版本；启动或重启该环境的 systemd 服务；检查服务和外部地址。新程序启动或本机健康检查失败时恢复前一版程序并报告失败步骤，不改另一套环境；仅外部地址检查失败时保留已启动程序，并提示检查 DNS、安全组或 Nginx。生产模式不得使用未提交的本地代码；测试模式不修改 Git 工作区。

两套服务的二进制、配置、日志和数据分别存放。线上凭据只保存在 ECS 的受限环境文件中，不写入脚本、Git 或命令行。数据库迁移不在每次部署时自动运行；首次线上启用或数据库结构变化时单独执行并备份。

## 一次性前提

Mac 能通过 SSH 22 登录 `root@39.105.122.224`。IP 测试需要在阿里云安全组中允许受信任来源访问 8082。用户手动配置 Nginx 和 HTTPS：线上域名反向代理到 `127.0.0.1:8081`；若需要测试域名，反向代理到 8082。Nginx 配置和证书不由脚本变更。正式小程序使用配置好的 HTTPS 域名。

线上首次启动还依赖生产代码已合入 `main`、独立 MySQL 数据库及表结构就绪、ECS 上已设置微信和数据库凭据。脚本只验证这些前提，不能代替其准备工作。
