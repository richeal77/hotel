# 微信小程序到店支付版人工接入清单

日期：2026-11-17

适用范围：高碑店尚客优单店小程序，微信登录、微信手机号授权、在线提交预订、前台确认、到店付款。保留原方案的扫码入会和推荐分享。配套研发方案见[迭代需求与方案设计](superpowers/specs/2026-11-17-wechat-offline-booking-design.md)。

本版无需申请微信支付商户号、购买短信套餐或申请 PMS 接口。仍需完成小程序认证、服务类目、备案、域名 HTTPS 和数据库部署。微信手机号能力面向完成认证的非个人主体，因此不应以个人主体注册本项目。[微信手机号能力说明](https://developers.weixin.qq.com/miniprogram/dev/framework/open-ability/getPhoneNumber.html)

## 1 需要准备哪些外部资源

| 事项 | 本版处理 | 人工工作与费用性质 |
| --- | --- | --- |
| 微信小程序账号与认证 | 必需 | 使用门店实际经营主体；认证费用按后台实际展示缴纳 |
| 住宿服务类目 | 必需 | 提交对应经营资质，与在线预订功能一致 |
| 小程序备案 | 必需 | 在微信公众平台办理 |
| 微信登录 | 必需，代码已有 | 配置正确的 AppID 和服务端 AppSecret，无需找登录供应商 |
| 微信手机号授权 | 必需，代码已有 | 确认权限和可用额度；用完体验额度后购买资源包 |
| 域名与 ICP 备案 | 当前 ECS 部署路线必需 | 使用真实主体实名域名，通过实际服务器接入商办理 |
| HTTPS | 必需 | 配置有效证书及续期；免费证书也可满足技术要求 |
| 后端与 MySQL | 必需，部署方案已有 | 可复用已准备的 ECS；数据库可自建或托管，必须有备份和恢复验证 |
| 门店和个人推荐小程序码 | 保留原产品需求 | 使用同一小程序的微信生成码能力；不额外找二维码供应商 |
| 微信订阅消息 | 本次建议后置 | 首版依靠后台待确认订单和前台电话确认，不承诺自动微信提醒 |
| 短信、在线支付、PMS、公安系统、电子发票接口 | 本版不接 | 继续使用门店原有收款、入住登记和开票流程 |
| 对象存储、CDN、地图 Web API | 非必购 | 小程序码先由现有服务器保存；地址展示不依赖地图供应商 |

是否已完成认证、备案、是否已有可复用域名和数据库，需要管理员在各后台逐项核实。仓库里已有 AppID 和部署脚本，不代表这些事项已经完成。

## 2 老板和管理员的办理步骤

| 顺序 | 谁负责 | 去哪里做什么 | 完成标志 |
| --- | --- | --- | --- |
| 1 | 老板 | 确认营业执照主体是公司还是个体工商户；确定小程序管理员、联系人和管理邮箱 | 主体与实际门店一致，账号由经营方掌握 |
| 2 | 老板或管理员 | 在[微信公众平台](https://mp.weixin.qq.com/)注册“小程序”，已有账号则核对主体、AppID、管理员和认证状态；不要重复注册 | 能登录正确账号，完成主体认证 |
| 3 | 管理员 | 完善名称、头像、简介，选择符合实际功能的“旅游服务／住宿服务”类目，按页面提交材料 | 类目审核通过；使用“尚客优”名称或标识时备妥有效品牌授权材料 |
| 4 | 管理员，技术协助 | 在微信公众平台“小程序备案”入口提交主体、负责人、小程序和服务信息；按提示配合身份核验、短信核验和审核补充 | 小程序备案完成，可查询对应备案信息 |
| 5 | 老板或云账号管理员，技术协助 | 确认域名和大陆服务器，完成域名实名，通过实际接入商办理 ICP 备案；已有备案按接入商要求办理新增接入或变更 | 备案信息与实际部署一致 |
| 6 | 管理员 | 在成员管理中添加开发者和体验成员；在开发设置中核对 AppID，生成或安全交付 AppSecret | 技术人员有必要权限，密钥只进入服务器受限配置 |
| 7 | 管理员 | 在“付费管理”查看手机号快速验证权限、体验额度和资源包；额度不足时按需求购买 | 开发／体验环境能够成功授权一次手机号 |
| 8 | 老板或店长 | 确认门店电话、地址、房型、展示价格、会员规则、隐私联系渠道；确定轮班查看待确认订单的人 | 真实经营配置和前台流程可用于验收 |
| 9 | 管理员，技术协助 | 在后台填写用户隐私保护指引，覆盖手机号、订单联系人、会员权益和来源记录等实际处理信息；核对小程序内可阅读的规则 | 已声明手机号用途，隐私授权流程可用 |
| 10 | 管理员与前台 | 验收体验版，提交代码审核；通过后发布。发布后复核正式小程序码，再印制前台、房卡等物料 | 普通住客在关闭调试模式时可完成预订 |

注册的标准入口和主体说明见[腾讯客服注册指引](https://kf.qq.com/faq/170109iQBJ3Q170109JbQfiu.html)。不接支付意味着不必为本项目申请支付结算账户；认证过程中若后台要求账户验证或其他主体核验，仍按所选认证路径办理，不能把两者混为一谈。

微信当前“住宿服务”类目对单家主体列出的材料是：经营范围含住宿等内容的营业执照，或经营范围含旅馆业的特种行业许可证。平台类目材料要求与门店线下经营许可不是同一件事，以实际经营情况和后台要求提交。[微信服务类目说明](https://developers.weixin.qq.com/miniprogram/product/material/)

小程序备案和服务器域名 ICP 备案分别办理。微信小程序在微信公众平台备案；沿用项目的阿里云 ECS 路线时，服务器域名备案在阿里云办理，阿里云不代办微信小程序备案。[腾讯云关于微信小程序备案入口的说明](https://cloud.tencent.com/document/product/243/97691)、[阿里云备案入口说明](https://help.aliyun.com/zh/icp-filing/basic-icp-service/support/faq-about-icp-filing-preparations)

手机号快速验证的官方标准单价为每次成功调用 0.03 元，每个小程序有 1,000 次开发、体验、正式版共用的体验额度；套餐金额、有效期和剩余额度以付费管理页为准。建议首次绑定或主动更换手机号时调用，日常登录复用已有绑定。[微信收费说明](https://developers.weixin.qq.com/miniprogram/dev/framework/open-ability/getPhoneNumber.html)

## 3 技术人员的一次性配置

这些工作不是让老板购买新服务。技术人员可沿用[后端部署说明](deployment-api.md)和[MySQL 与真实认证方案](architecture/mysql-phase2.md)完成。

1. 准备独立测试库和生产库，执行数据库迁移，建立正式员工账号，初始化真实门店配置与入会礼模板。不要将演示住客、测试订单和演示员工导入生产业务库。
2. 在服务器受限配置中设置 `APP_ENV`、`MYSQL_DSN`、`WECHAT_APP_ID`、`WECHAT_APP_SECRET`。真实 AppSecret、数据库密码不进入小程序、Git 或聊天正文。
3. 配置 `api.<实际域名>` 的 DNS、HTTPS 和 Nginx 转发；工作台也使用 HTTPS。核实数据库备份、证书续期和服务异常告警的责任人。
4. 在小程序后台配置 `request` 合法域名，例如 `https://api.<实际域名>`，不带 `/api/v1` 路径；小程序业务 API 地址才使用 `https://api.<实际域名>/api/v1`。如下载小程序码图片，再配置实际使用的 `downloadFile` 合法域名。
5. 微信 `access_token` 接口若要求 IP 白名单，将服务器实际出网 IP 按后台要求加入。服务器调用 `api.weixin.qq.com`；不要把它当作前端请求域名配置。
6. 完成正式包的生产模式锁定，去除住客可操作的演示开关、任意 API 地址入口和测试默认内容，启用域名校验。正式版不能靠“开启调试／不校验合法域名”才能工作。
7. 按微信隐私机制打通协议展示、用户同意与手机号授权；页面里的普通开关不能单独作为已完成微信隐私授权的证明。
8. 生成并缓存门店渠道码与个人推荐码；体验物料指向体验版，正式物料指向正式版。扫码验证来源、页面和推荐人后再印制，不把开发工具预览码作为长期物料。
9. 执行设计文档中的真实账号验收，保存通过的发布版本、配置项清单和数据库备份记录。

微信要求该自建后端路线使用配置过的 HTTPS 通讯域名，域名经过 ICP 备案，且 AppSecret 放在后端。[微信网络配置要求](https://developers.weixin.qq.com/miniprogram/dev/framework/ability/network.html) 隐私保护指引及授权衔接按[微信隐私协议开发指南](https://developers.weixin.qq.com/miniprogram/dev/framework/user-privacy/PrivacyAuthorize.html)配置。

## 4 上线时前台怎么操作

住客提交后显示“待门店确认，到店付款”。前台值班时保持工作台打开并处理待确认订单；核对原有酒店系统的房态，通过受控入口查看联系电话并致电确认，再将订单改为“已确认”。本版不会自动占用 PMS 库存，也不会在住客关闭小程序后自动发送订阅消息或短信。

到店入住、收款和开票继续走原流程。离店时前台核对实际实收房费，明确确认“已线下结清”后再完成小程序订单及权益发放。电话未接通、无房或取消的订单由前台按门店规则处理，不能仅因客人点击提交就承诺房间已保留。

正式开启自动发奖前，还需具备已结清订单的金额纠错／线下退款记录与关联权益撤回流程。现有手工调余额不能替代完整纠错；这属于内部开发前置项，不需要另购支付服务，具体边界见设计第 6.1 节。

## 5 交给技术人员的结果清单

- [ ] 正确的小程序 AppID、主体名称及认证状态。
- [ ] 类目和备案审核结果；品牌名称使用材料已按要求准备。
- [ ] 开发者权限、体验成员权限。
- [ ] AppSecret 已通过安全配置方式交付，不填写在本清单中。
- [ ] 手机号权限可用、额度充足，指定余额检查负责人。
- [ ] 域名、备案结果、HTTPS 地址、服务器出网 IP。
- [ ] 独立测试和生产数据库及备份方式。
- [ ] 真实门店电话、地址、房型、价格、规则、隐私联系渠道。
- [ ] 前台轮班责任、待确认订单处理方式、线下实收登记方式。
- [ ] 体验版验收通过、代码审核通过、正式码扫码验证通过。

认证、类目、备案、资源包和云资源的实际审核状态及费用以各后台为准。现有仓库内容不足以确认这些人工事项已经完成。
