# 第二阶段测试环境验收用例

日期：2026-11-17

依据：`docs/contracts/openapi.yaml`、`docs/contracts/phase-2-changes.md`、`docs/superpowers/specs/2026-11-17-wechat-offline-booking-design.md`。本文件是验收标准，不表示功能已实现或已在测试环境通过。

## 1. 执行门槛与证据

- 仅对独立 `APP_ENV=integration` 测试环境执行写入、重启和恢复；先核实环境标识、测试域名、独立 MySQL 库、AppID、后台地址、代码版本与测试数据可清理范围。不得在生产库或默认 `local-demo` 上代跑。
- 微信真实登录和手机号授权必须在目标 AppID 的体验版真机完成。模拟器、伪造 code、单元测试或 HTTP 通路不能替代真机通过。验收前确认账号已认证、手机号能力可用、隐私指引及 HTTPS 合法域名已配置。
- 使用两个受控测试微信号 A/B 和各自不同手机号；准备老板、前台、财务测试员工。所有密码和密钥通过受限渠道提供，不进入用例、命令输出、截图或 Git。预订金额使用可核对的测试价；线下付款只做测试记录，不发生真实支付。
- 每例记录：时间、环境/版本、操作者、测试数据 ID、页面截图或录屏、请求 ID/HTTP 状态、后台记录及数据库只读核对。截图遮蔽完整手机号、token、微信 code 和数据库密钥。
- 判定为 `通过 / 失败 / 阻塞 / 未执行`。页面、API、真机分别判定；不能用一种证据代替另一种。失败记录最短复现步骤、实际响应、关联文件或接口及归属 AI。
- 备份恢复前核对目标为**新建的隔离恢复库**，记录快照时间与校验值。绝不将备份导回正在运行的验收库或生产库；不得为测试关闭证书校验、权限控制或审计。

## 2. 核心业务链路

| 编号 | 操作与前置条件 | 预期结果 | 必留证据 |
| --- | --- | --- | --- |
| P2-01 | 查环境配置及路由：测试服务、数据库、AppID、HTTPS 域名；未授权访问 `/admin/demo/state`；**确认已连接 integration 后**用空请求探测 `/auth/mock-login`。 | 服务为 `integration` 且只连独立测试库；演示路由 404；微信真实认证路由存在；小程序显示“真实微信接口”，域名校验开启。 | 脱敏配置核对、HTTP 状态、项目及真机设置截图。 |
| P2-02 | A 在体验版真机首次打开，执行微信登录；拒绝手机号授权后浏览门店。 | 微信 code 换成后端会话；无手机号不被伪绑定；公开门店电话/地址可看，不能提交需手机号的预订。 | 真机录屏、会员 ID 与脱敏服务端记录；不得留存短期 code。 |
| P2-03 | A 阅读隐私和会员规则，同意微信原生隐私授权，点击手机号授权并入会，选择洗衣券。 | 绑定的是微信返回的手机号；会员状态正确，洗衣券恰好 1 张；不发送固定短信，也不返回 `666666`。 | 真机成功页、后台会员/券查询、券 ID、计数前后值。 |
| P2-04 | A 退出再登录、会话失效后登录；重复提交同一入会请求，或模拟绑定成功后入会响应中断再重试。 | 复用同一会员；不再次要求无必要的手机号付费授权；不重复发券、不重复建会员。 | 前后会员/券数量、会话状态、重试响应。 |
| P2-05 | A 提交两晚预订并到店付款；填日期、有效房型、联系人、已绑定手机号。 | 参考房费与间夜相符；状态待门店确认；未填实际收款金额、未标已支付；我的订单与后台同一订单 ID 一致。 | 真机页面、后台列表、订单 API 响应和订单 ID。 |
| P2-06 | 前台打开待办，按权限查看该订单联系电话并致电核对房态，确认订单、标记入住。 | 列表仍脱敏；受控单笔查看返回完整电话且有查看审计；订单状态顺序正确，小程序可见状态变化。 | 后台页面、脱敏列表、审计 ID、订单状态时间线。 |
| P2-07 | 对 P2-05 的两晚订单核对线下实收 80 元（明确记录测试优惠后的实收与参考价差异）并确认结清；随后查看权益。 | 订单已离店且实收 8000 分；按 3% 发 240 分返住金一次，不能按两晚参考价发奖；推荐奖励仅在满足推荐条件时发放；住客余额、流水与后台一致。 | 订单、钱包流水、真机返住金页、后台查询。 |
| P2-08 | 前台按 A 的手机号或会员码查洗衣券，关联正确订单核销，随后重复提交。 | 首次核销成功、券已使用；第二次明确失败，不增加核销计数或审计成功记录。 | 核销页、两次 HTTP 状态、券状态与计数。 |
| P2-09 | 读取同一天及本月老板看板，比较 P2-03/05/07/08 前后。 | 当日入会、订单、核销及本月返住金发放分别增加 1/1/1/240 分；返住金“核销”不因发放而增加；日期口径一致。 | 同日期前后截图与 API 数值。 |

## 3. 异常、权限与重复请求

| 编号 | 操作与前置条件 | 预期结果 | 必留证据 |
| --- | --- | --- | --- |
| P2-10 | 拒绝手机号授权、过期/复用微信 code、微信服务超时或额度不足。 | 明确错误且可重试；无假绑定、无 `666666`/本地演示回退；无重复会员或券。 | 真机提示、HTTP 状态、计数前后值。 |
| P2-11 | B 访问 A 的会员/订单/钱包/券，或用 B 的订单核销 A 的券；伪造他人手机号及推荐人参数。 | 跨会员读取或写入被拒绝；券与订单会员不一致被拒绝；客户端参数不能覆盖已验证的微信手机号/来源。 | HTTP 403/409 等实际状态、脱敏审计、资产不变。 |
| P2-12 | 未登录、会员 token、财务 token、前台 token 分别访问老板看板、规则、单笔订单联系信息及改价/核销接口。 | 按角色矩阵返回 401/403；只有被授权员工能看单笔完整电话，列表始终脱敏；失败不泄露号码。 | 各身份状态矩阵、响应脱敏检查、审计。 |
| P2-13 | 同一会员并发发送两次完全相同预订请求及相同幂等 key；再以同 key 改日期/房型。 | 相同请求仅 1 张订单且返回同一 ID；不同内容冲突，不出现双单。 | 请求 ID、HTTP 状态、订单计数。 |
| P2-14 | 未填实收/未确认线下结清、零元无原因、重复离店、同幂等 key 改金额。 | 非法离店被拒且不发奖；重复成功请求只结算一次；冲突金额被拒，账本无重复流水。 | 订单状态、权益流水与请求状态。 |
| P2-15 | 已使用、过期、黑名单券分别核销；使用别的会员订单核销。 | 均失败，券状态及核销计数不变；无越权读取。 | HTTP 状态、券明细、审计。 |
| P2-16 | 管理端与小程序注销会话后重放旧 token；检查工作人员列表、审计、日志。 | token 失效；手机号按角色脱敏；日志无密码、AppSecret、微信 code 或完整手机号。 | 注销前后状态、脱敏日志抽样。 |

## 4. 持久化与恢复

| 编号 | 操作与前置条件 | 预期结果 | 必留证据 |
| --- | --- | --- | --- |
| P2-17 | 记录 A 会员、订单、券、钱包流水、推荐来源及有效会话；仅在独立测试环境重启 API 进程。 | 业务 ID、金额、状态和有效会话仍可读取；无重复发奖；未动生产服务。 | 重启前后只读查询、服务状态、版本。 |
| P2-18 | 经测试环境负责人许可，重启独立测试 MySQL；再次查询 P2-17 数据。 | 业务和会话数据保持一致，API 恢复可用；无跨环境影响。 | 数据库/服务状态、前后计数与校验。 |
| P2-19 | 对独立测试库制作一致性备份，记录校验值；恢复到新建隔离库并只读比较关键表及抽样业务链。 | 备份可读取；恢复库中会员、订单、券、钱包流水、会话和审计数量及关联一致；原测试库不变。 | 备份时间/大小/校验值、恢复库名脱敏、表计数与关联检查。 |
| P2-20 | 恢复完成后核对当前验收库及生产库未被替换；清理仅本轮可丢弃测试数据。 | 两环境边界保持；清理有记录，生产数据不变。 | 前后环境标识、操作审计、数据计数。 |

## 5. 放行规则

P2-01 至 P2-09、P2-11 至 P2-14、P2-17 至 P2-19 为本轮发布阻断项。P2-10、P2-15、P2-16 至少覆盖列出的关键负例；未能制造的外部故障要标“未执行”，不能标通过。真实微信授权、真机请求、独立 MySQL 重启和隔离库恢复缺一项时，不能宣称第二阶段端到端或灾备验收完成。对设计文档中仍属待实施的联系信息、幂等、实收确认、真实小程序码等能力，应如实记为未实现/失败，不降低预期。
